# Админка Clymly

Адрес: `https://clymly.ru/admin` (вкладки «Обзор», «Пользователи», «Платежи», «Маркетинг», «Интеграции»).
`/admin/integrations` — прежняя аналитика JobToo, работает как раньше.

## Доступ
Только вошедший пользователь, чей e-mail (из сессии в БД) указан в переменной `ADMIN_EMAILS`. Проверка — на сервере
в макете раздела, на каждой странице (`requireAdminPage`) и в каждом API (`requireAdminApi`). Чужим и без входа —
«Страница не найдена» / 404 (существование раздела не раскрывается). Ссылки на админку в меню кабинета нет.

## Определения метрик
* Сутки и периоды — по московскому времени. «7 дней» — сегодня и 6 предыдущих суток.
* **Активный пользователь** — за 30 дней входил в аккаунт или пользовался сервисом (резюме, вакансия, письмо, тренажёр, оплата).
* **Подтверждённые оплаты** — платежи `succeeded`. Ожидающие (`pending`), отменённые (`canceled`) и «требуют проверки» (`issue`) в выручку не входят.
* Тариф покупки — из заказа: `Pro · 1 месяц` / `Pro · 3 месяца` (по сумме не определяется). «Покупки по тарифам»: число оплаченных заказов, выручка и уникальные покупатели по каждому тарифу.
* Провайдер: Тестовый / ЮKassa / ЮMoney; в таблице — номер заказа, id транзакции у провайдера и история статусов. Подробнее — `docs/payments.md`.
* «Последняя зафиксированная активность» — вход, загрузка резюме, анализ вакансии, письмо, ответ в тренажёре, создание заказа; просмотры страниц не отслеживаются (иначе «Нет данных»).
  Это оборот, не прибыль. Возвратов в системе нет. MRR не считается: Pro разовый (1 или 3 месяца), без автопродления.
* Платёж относится к периоду по дате создания. Суммы не конвертируются между валютами (сейчас все платежи в рублях).
* **Подписка**: «Активна» — Pro оплачен на сегодня; «Истекла» — оплачивался, срок прошёл; «Не оформлялась».
  Отменённых подписок нет — отмены в системе не предусмотрено. Начало — первая оплата текущего непрерывного периода.
* Блокировки аккаунтов в системе нет; статус «Не принял условия» — аккаунт создан переходом из JobToo, вход не завершён.

## Маркетинговые ссылки и атрибуция
* Ссылка: `https://clymly.ru/go/<slug>` (по умолчанию `instagram`), новые создаются во вкладке «Маркетинг».
  UTM из адреса (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`) важнее меток ссылки;
  допускаются латиница, цифры, `-_.`, до 64 символов, остальное отбрасывается. Редирект — только на внутренний путь
  из настроек ссылки (по умолчанию `/`), параметры запроса на него не влияют.
* Переход записывается на сервере (`Visit`): время, ссылка, UTM, домен реферера, посадочная страница, тип устройства,
  ОС, браузер, язык. **IP не сохраняется** (используется только как ключ лимита частоты в памяти), отпечаток не строится,
  страна и регион не определяются.
* Посетитель — случайный id в first-party cookie `cl_vid` (90 дней). Уведомление об аналитических cookie показывается
  пришедшим по ссылке. Отказ: cookie удаляется, переходы обезличиваются и отвязываются от аккаунта, атрибуция снимается;
  дальнейшие переходы учитываются только как клики без идентификатора.
* Регистрация: визиты посетителя связываются с аккаунтом. **First-touch** — самый ранний визит до регистрации
  (`User.firstVisitId`), **last-touch** — последний визит перед регистрацией (`User.signupVisitId`).
* Вход: визиты посетителя связываются с аккаунтом (для атрибуции будущих оплат), источник регистрации не меняется.
  Поэтому существующий аккаунт, пришедший по ссылке, не считается регистрацией.
* Оплата: first-touch — по first-touch пользователя; last-touch — последний визит пользователя не позже создания платежа.
  Модели переключаются и никогда не смешиваются в одной метрике.
* Уникальные посетители — различные `cl_vid` среди переходов периода. Конверсии:
  регистрации / уникальные × 100%; оплатившие (уникальные пользователи) / уникальные × 100%; при нуле — «—».
* JobToo: аккаунты из JobToo (`User.source = 'jobtoo'`) в маркетинговую атрибуцию не входят; их аналитика — во вкладке
  «Интеграции». Выручка JobToo не учитывается (интеграция не передаёт сведений об оплатах в JobToo).

## База данных
Изменения только добавляют таблицы и поля (`prisma db push` при старте, как и раньше): `MarketingLink`, `Visit`,
`User.firstVisitId`, `User.signupVisitId`, `Session.createdAt`, индексы `User(createdAt)`, `Payment(createdAt, status)`,
`Session(userId, createdAt)`. Ссылка `instagram` создаётся сидом. У старых пользователей маркетинговых данных нет —
источник «Неизвестен».

## Тесты
`node scripts/admin-e2e.mjs` (права, ссылки, атрибуция, пользователи, платежи, обзор), `node scripts/admin-ui.mjs`
(Chromium, desktop и mobile). Сервер запускается с `ADMIN_EMAILS=admin_e2e@example.com`.
