# Оплата Pro: тарифы, заказы, провайдеры

## Тарифы (единый источник — `src/lib/billing/plans.ts`)

| id предложения | Название в интерфейсе | Метка в админке | Срок | Цена |
|---|---|---|---|---|
| `free` | Free | Free | — | 0 ₽ |
| `pro-month` | Pro — 1 месяц | Pro · 1 месяц | 1 календарный месяц | 499 ₽ |
| `pro-quarter` | Pro — 3 месяца | Pro · 3 месяца | 3 календарных месяца | 1 190 ₽ (≈ 397 ₽/мес, экономия 307 ₽ ≈ 20,5 % против 3 × 499 ₽) |

id предложений стабильны (уже хранятся в старых заказах). Эквивалент в месяц и экономия вычисляются из цен.
Pro оплачивается разово, без автопродления. Повторная покупка во время активного Pro добавляет срок к концу текущего периода.

## Заказ и статусы

Одна запись `Payment` = один заказ. При создании сохраняется снимок: `planId`, `planName`, `months`, `amount`, `currency`, `provider`.
После подтверждения — `providerPaymentId` (id у провайдера), `paidAt`, `accessFrom`, `accessUntil`.
История статусов — `PaymentEvent` (создание, подтверждение, повторы, отклонённые уведомления).

* Статус платежа: `pending` → `succeeded` | `canceled` (переход только из `pending`, поэтому повторы не продлевают Pro).
* Состояние заказа (для интерфейса): ожидает оплаты / оплачен / не оплачен / требует проверки (`issue` не пустой).
* Доступ Pro: `User.plan/planUntil`; период конкретного заказа — `accessFrom..accessUntil`.

Цена, срок и пользователь определяются только на сервере. Повторный запрос на тот же тариф тем же способом в течение 30 минут
возвращает существующий незавершённый заказ (параллельные запросы сериализуются блокировкой).

Страница возврата `/billing/result?order=…` показывает итог по данным сервера (параметры адреса не учитываются).

## ЮKassa (способ «карта», `PAYMENT_PROVIDER=yookassa`)

Без изменений: API v3, уведомления на `/api/billing/webhook`, статус всегда перепроверяется запросом к API.

## ЮMoney (`YOOMONEY_ENABLED=1`)

Сценарий — официальный «API для сбора денег» ЮMoney для кошелька: форма Quickpay + HTTP-уведомления.

1. Пользователь выбирает «Оплатить через ЮMoney» → создаётся заказ → `/pay/yoomoney/<id>`.
2. Страница отправляет форму на `https://yoomoney.ru/quickpay/confirm`: `receiver` (кошелёк), `sum`, `label` = номер заказа,
   `paymentType` = `AC` (карта) или `PC` (кошелёк), `successURL` = страница результата.
3. ЮMoney присылает уведомление `POST /api/billing/yoomoney` (`application/x-www-form-urlencoded`).
4. Проверки: подпись `sign` (HMAC-SHA256 по отсортированным параметрам, ключ — секрет уведомлений; устаревший `sha1_hash`
   поддержан как запасной), формат полей, заказ существует и принадлежит ЮMoney, `withdraw_amount` = сумма заказа,
   валюта 643, `unaccepted`/`codepro` = false, операция не привязана к другому заказу; при заданном
   `YOOMONEY_ACCESS_TOKEN` — дополнительно `operation-details` (статус success, направление in, тот же label).
5. Только после этого заказ оплачен и Pro продлён. Несовпадения → заказ «требует проверки», Pro не включается.

Ответы: 200 — принято (в т.ч. отклонено по сути и записано), 400 — формат/подпись, 500 — временная ошибка сверки (ЮMoney повторит),
404 — ЮMoney выключен, 503 — включён, но не настроен.

Ограничения: у формы Quickpay нет API создания платежа и ключа идемпотентности; статус по запросу без OAuth-токена не проверить —
Pro включается только по уведомлению. Возвратов нет. Данные карт Clymly не получает.

## Автопродление и несколько карт (ЮKassa)

Модуль `src/lib/billing/autopay.ts`, клиент API — `src/lib/billing/yookassa.ts`, планировщик — `src/instrumentation-node.ts` (раз в 10 минут).

* Включается только по согласию: галочка «Запомнить данные карты» на странице ЮKassa (`payment_method.saved`) или
  «Привязать карту» в «Тариф и оплата» (проверочный платёж 1 ₽, `capture: false`, сразу отменяется). До 5 карт, одна основная;
  новая привязанная карта сразу становится основной, прежние остаются запасными.
  У нас хранятся только id способа оплаты и подпись «MasterCard •• 4444» (`UserCard`).
* Напоминание — за 1–5 дней до окончания Pro, 10:00–20:00 МСК (`REMINDER_HOURS`), сумма фиксируется (`autopayAmount`).
  Письмо не ушло — отметка снимается, списания нет.
* Списание — не раньше чем за сутки до окончания и не раньше чем через 3 дня после напоминания (и не позже 3 дней после
  окончания), с основной карты: `payment_method_id`, `capture: true`, без `confirmation`, `metadata.recurring=1`, чек,
  `Idempotence-Key` = номер заказа. Попытка «занимается» условным обновлением `autopayLastTry`.
* Неудачи: до 3 попыток с основной не чаще раза в 8 часов → по одной с каждой другой картой → автопродление выключается,
  карты удаляются. `permission_revoked`, `card_expired`, `payment_method_restricted`, `payment_method_limit_exceeded` — карта удаляется сразу.
* При действующем автопродлении можно купить только тариф с большим сроком (1 → 3 месяца); после покупки продлевается новый тариф.
* Полный возврат (`refund.succeeded`) — оплата «Возврат», срок сокращается на оплаченный период, автопродление выключается.
* Возврат с платёжной страницы в другой браузер: `/payment/return?order=…&r=…`, ключ одноразовый, 24 часа, в базе — sha256.
* Сверка: автосписания в pending старше 15 минут и привязки карт старше 5 минут запрашиваются у ЮKassa сами.

Уведомления: `https://<домен>/api/billing/yookassa` (прежний `/api/billing/webhook` тоже работает), события
`payment.succeeded`, `payment.waiting_for_capture`, `payment.canceled`, `refund.succeeded`. `YOOKASSA_IP_CHECK=1` — только с IP ЮKassa.

Тест: `node scripts/autopay-e2e.mjs` против имитатора `scripts/mock-yookassa.mjs` (см. заголовок файла).
