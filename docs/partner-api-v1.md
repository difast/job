# Clymly ⇄ JobToo: протокол v1 — сторона Clymly

Реализовано по документу JobToo «JobToo ⇄ Clymly. Версия протокола v1 · 10 октября 2026». Здесь — ответы Clymly по разделу 8 и детали нашей стороны.

## Ответы на «Что нужно от Clymly» (раздел 8)

1. **Страница приёма перехода:** `https://clymly.ru/partner/jobtoo/start?code=<код>`. Код сразу убирается из адресной строки (хранится только в httpOnly-cookie на 15 минут), в журналы и аналитику не попадает.
   **Адрес для ваших событий:** `POST https://clymly.ru/api/partner/v1/events` (`X-Partner-Id: jobtoo`), события `login_completed`, `account_linked`, `first_action`; `request_id` — наш `X-Request-Id` из handoff. События с неизвестным `request_id` игнорируются.
2. **pull и handoff:** реализованы. `POST https://jobtoo.ru/api/partner.php?op=pull` — только после согласия человека на нашей странице, без `clymly_user_id`. `POST …?op=handoff` — по кнопке «Перейти в JobToo» (главная, «Моё резюме», страница адаптации резюме).
3. **Тестовый стенд и секреты:** готовы подключиться к вашей заглушке. Нужен её адрес; два секрета передадим по защищённому каналу. У нас: `JOBTOO_OUTBOUND_SECRET` — Clymly → JobToo (pull, handoff, events), `JOBTOO_INBOUND_SECRET` — JobToo → Clymly (ваши события).
4. **Тексты согласия:**
   * перед получением данных от JobToo (страница `/partner/jobtoo/start`, версия `2026-10-10`): «Даю согласие на обработку персональных данных, в том числе полученных от JobToo, принимаю Пользовательское соглашение и ознакомлен(а) с Политикой конфиденциальности» — ссылки на https://clymly.ru/consent, /terms, /privacy. Перечень получаемых данных показан на странице;
   * перед передачей в JobToo (окно у кнопки «Перейти в JobToo», версия `2026-10-10`): перечень передаваемых данных (имя и e-mail; профессия и уровень; текст резюме и найденные навыки; адаптированная версия резюме), кому — JobToo, зачем — создать или найти профиль в JobToo, загрузить резюме и подобрать вакансии, срок — до отзыва; отзыв — «Настройки → Интеграции».
5. **Реквизиты:** ООО «Интегро», ОГРН 1257700559269, ИНН 9734021152, КПП 773401001, 123592, г. Москва, ул. Маршала Катукова, д. 22 к. 1. Договор — по пунктам раздела 7.

## JobToo → Clymly («Clymly забирает сам»)

1. `GET /partner/jobtoo/start?code=…` → страница с условиями Clymly и перечнем данных. До согласия Clymly ничего не запрашивает.
2. Отказ → событие вам `consent_declined`. Поскольку `handoff_request_id` до pull неизвестен, в нём `request_id = hex(sha256(code))` — **просим сопоставлять по хешу кода** (или предложите другой идентификатор).
3. Согласие → `POST …?op=pull` с `{ code, consent: { accepted_at, version } }`. Повтор — только при сетевой ошибке и 503 (не больше 2 раз, тот же `X-Request-Id`); на тайм-ауте не повторяем.
4. Аккаунт определяется так:
   * есть связь с `jobtoo_user_id` → вход;
   * e-mail уже есть в Clymly и подтверждён **и у нас, и у вас** (`email_verified=true`), а аккаунт не связан с другим JobToo → связь и вход;
   * иначе для существующего e-mail → экран привязки: человек входит своим паролем Clymly; связать можно только аккаунт **с той же почтой** и только при `email_verified=true`. Существующая связь не перезаписывается;
   * e-mail нет → новый аккаунт (согласие получено на странице приёма).
5. После входа — событие вам `login_completed` с `request_id = handoff_request_id`.

Файл резюме: `resume_file = { name, mime, data_b64 }`, PDF/DOCX/TXT до 5 МБ; расширение, MIME и содержимое должны совпадать. Если файл не читается, но есть `resume_text`, берём текст. Если резюме нет — человек видит понятную ошибку.

**Просьба:** добавить в payload pull поля `experience_level` и `utm: { placement, platform }` (необязательные). Без уровня человек выбирает его в Clymly; без `utm` в аналитике не видно, откуда переход.

## Clymly → JobToo (handoff)

JSON по вашему разделу 4: `source`, `clymly_user_id`, `jobtoo_user_id` (если связаны), `email`, `email_verified` (`true` — почта подтверждена по ссылке из письма Clymly), `name`, `target_position`, `target_position_id`, `experience_level`, `resume_id`, `resume_text`, `resume_adapted_text`, `skills_detected`, `consent`, `utm`. `login_url` открываем только на `https://jobtoo.ru/`. При `account=created` с пустым `external_user_id` связь не сохраняем.

## Данные и безопасность

* Данные хранятся и обрабатываются только в России (Timeweb Cloud), сторонние сервисы обработки за рубежом не используются.
* Коды перехода и ссылки входа не сохраняются в открытом виде и не пишутся в журналы и аналитику.
* Аналитика переходов в обе стороны — без персональных данных; сопоставление с JobToo по `request_id`.
