# ИИ в Clymly

## Функции и путь запроса

| Функция | Интерфейс | API | Что делает ИИ | Серверные проверки |
|---|---|---|---|---|
| Анализ резюме | «Моё резюме» → загрузка файла; смена профессии в настройках | `POST/PUT /api/resume`, `PATCH /api/profile` | оценка по 6 критериям, сильные стороны, что улучшить, недостающие навыки, что не удалось оценить | «похоже ли на резюме» до и после ИИ; общий балл = среднее критериев; длинный текст — с пометкой |
| Сравнение с вакансией | «Вакансии» → вставить текст | `POST /api/vacancies` | требования, статус по резюме, цитата-подтверждение, советы | «похоже ли на вакансию»; совпадение без найденной в резюме цитаты → «не хватает»; балл пересчитывается по требованиям |
| Адаптация резюме | вакансия → «Адаптировать резюме» | `POST /api/vacancies/:id/adapt` | правки отдельных строк | отбрасываются правки с новыми числами, терминами, названиями, словами вакансии, которых нет в резюме, заглушками, строками контактов |
| Сопроводительное письмо | «Письма» | `POST /api/cover-letters` | письмо в выбранном стиле | без заглушек, чисел и технологий, которых нет в резюме и вакансии (иначе одна перегенерация, затем ошибка) |
| Вопросы под вакансию | «Собеседования» → выбрать вакансию → «Начать» | `POST /api/interview/vacancy-questions` | 5 вопросов с ключевыми пунктами и шаблоном ответа | генерируются один раз на вакансию и тип, доступны только владельцу |
| Оценка ответа | «Собеседования» → ответ | `POST /api/interview/answer` | 4 критерия, объяснение, советы, улучшенный ответ; учитывает прошлую попытку и фокус вакансии | балл = взвешенная сумма критериев; пункты — только из списка; улучшенный ответ с новыми числами не показывается |

Общий банк вопросов собеседований — подготовленный, не ИИ.

Все функции идут через `src/lib/ai/index.ts` → `llm.ts` (проверка JSON по схеме, одна попытка исправить формат)
→ `provider.ts` → `providers/gigachat.ts` или `providers/anthropic.ts`. Системные инструкции — `src/lib/ai/prompts.ts`.

## Режимы

`AI_PROVIDER` = `gigachat` | `anthropic` | `none`; пусто — GigaChat, если задан `GIGACHAT_AUTH_KEY`, иначе Anthropic при `ANTHROPIC_API_KEY`, иначе `none`.

* `none` — упрощённый режим без ИИ: результат строят правила на сервере, на экране пометка «Упрощённый анализ без ИИ».
* Провайдер выбран, но не настроен — приложение работает, AI-функции отвечают 503 «сервис настраивается», в логе при старте — причина (имя переменной).
* Провайдер настроен, но не ответил / ответил не по формату — пользователь получает понятную ошибку и может повторить. Результат правил при этом **не** подставляется.

## Настройка GigaChat

1. developers.sber.ru → GigaChat API → проект → «Ключ авторизации» (Authorization key, Base64).
2. Переменные (Timeweb → приложение → Переменные окружения):
   * `AI_PROVIDER=gigachat`
   * `GIGACHAT_AUTH_KEY` — ключ авторизации, без слова `Basic`;
   * `GIGACHAT_SCOPE` — `GIGACHAT_API_PERS` (физлица), `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`;
   * `GIGACHAT_MODEL` — `GigaChat-2-Pro` (по умолчанию), `GigaChat-2` или `GigaChat-2-Max`;
   * `GIGACHAT_CA_CERT` — сертификаты Минцифры в формате PEM (корневой Russian Trusted Root CA и при необходимости
     промежуточный): содержимое файлов целиком или путь к файлу. Без них Node.js не доверяет серверам GigaChat.
3. Необязательно: `GIGACHAT_API_URL` (по умолчанию `https://api.giga.chat/v1`; прежний `https://gigachat.devices.sberbank.ru/api/v1`),
   `GIGACHAT_AUTH_URL`, `GIGACHAT_TIMEOUT_MS` (45000), `GIGACHAT_MAX_RETRIES` (2), `GIGACHAT_STRUCTURED_OUTPUT=1` (бета, JSON-схема ответа).
4. После деплоя в логе: `[ai] провайдер gigachat, модель …`; `GET /api/health` → `"ai": {"provider": "gigachat", "configured": true}`.

Протокол: токен `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth` (Basic-ключ, RqUID, scope), действует 30 минут, кешируется
и обновляется за минуту до истечения; генерация `POST {GIGACHAT_API_URL}/chat/completions` с Bearer-токеном.
Повторы: 429/5xx/сеть — до `GIGACHAT_MAX_RETRIES` с паузой (Retry-After); 401 — одна повторная авторизация за запрос.

## Данные

В модель уходит только нужное для задачи: текст резюме (контакты заменены на `[email]`, `[телефон]`, `[ссылка]`), вакансия,
вопрос и ответ. В логи пишутся тип ошибки и диагностика — без текстов, ключей и токенов. Лимит: 30 запросов к ИИ за 10 минут
на пользователя и 120 в минуту на сервис. Пользовательский текст передаётся в тегах и по инструкции считается данными.

## Тесты

* `npm test` — сетевой слой GigaChat и AI-функции на мок-сервере, валидаторы (без реального API).
* `node scripts/ai-e2e.mjs` — сквозной путь через приложение и мок GigaChat (см. заголовок файла), включая интерфейс.
* `npm run ai:live` — ~15 реальных запросов к GigaChat с критериями качества (нужны переменные GIGACHAT_*).
